# 預先登記:雷達「題材群聚」與「多來源」規則的評估(2026-11-15 登記)

本文件在看到評估結果之前寫下,登記後不得依結果修改方法、門檻或樣本數。若需修改,另開新版本並保留本版。

## 問題
雷達 A 區有兩種收錄規則:
- **題材群聚**(`theme_cluster`):同一檔被 ≥ 3 個關鍵字命中(依 2026-09-16 單一案例訂定);
- **多來源**(`source_diversity`):同一檔被 ≥ 2 種偵測來源命中。

要回答:這兩種規則挑出的股票,是否比「只因關鍵字暴增被列出」(`keyword_surge`,D 區前 5 檔)的股票表現更好。

## 資料
- `verification_ledger.json` 已裁決的紀錄(標記後 30 天),只用有 `excess_pct` 的紀錄。
- 超額報酬 = 個股 30 天報酬 − 加權指數同期報酬(百分點)。加權指數是市值加權,只當共同基準,不解讀絕對水準。
- 只用 2026-11-15 之後首次看到的評估結果;登記前已裁決的紀錄也納入(無法事後排除),但結論以「標記日數」為樣本單位。

## 方法
1. 每個標記日,分別算 A 規則(`theme_cluster` 或 `source_diversity`,兩者分開評估;`dual` 併入兩者)與 `keyword_surge` 的平均超額報酬。
2. 只用「兩者在同一標記日都有紀錄」的日子(配對),差值 = A 規則日平均 − keyword_surge 日平均。
3. 統計量:配對差值的平均;以標記日為單位 bootstrap 2,000 次,取 95% 信賴區間(固定亂數種子 20261115)。
4. 最低樣本:配對標記日 ≥ 30。不足時只回報「樣本不足」,不給結論。

## 判定(登記)
- 信賴區間下限 > 0:有證據顯示該規則挑出的股票優於只有關鍵字暴增的股票 → 保留規則。
- 信賴區間上限 < 0:有證據顯示較差 → 建議移除規則(仍由使用者決定)。
- 信賴區間含 0:沒有證據顯示有差別 → 頁面維持「未經驗證」,不宣稱任何優勢;是否保留由使用者決定。

## 不做的事
- 不調整 3 個關鍵字、2 種來源、30 天、+10% 等門檻後重跑。
- 不挑選子期間或排除特定日期。

## 實作
`radar_eval.py`(每天在 event-theme.yml 驗證台帳之後執行)輸出 `radar_eval.json`,題材頁命中率橫幅顯示狀態。
